# 官网实施与验收计划

依据工作区《Empact_China_官网建设计划_v1.1.md》，2026-09-09。

## 已确定的实施决策

- Astro 静态生成，Payload CMS 3 + Next.js + SQLite 独立运行；CMS 是运营内容唯一编辑来源。
- 单一可信运营账号；初始账号由本机命令初始化，禁止 HTTP 公开注册；内容、原始媒体和预览均鉴权。
- 固定导航和模板由代码维护。业务、项目、新闻、案例与报道统一建模但按种类编辑；案例/报道嵌入相关页面。
- 发布时冻结可公开快照，构建检查通过后原子切换静态目录；旧站与草稿隔离，失败保留旧站。发布记录只在验证后报告成功。
- 对原计划“CI 构建后传到 ECS”的实现细化：CI 验证代码和同一套构建模板；运营内容在官网服务账号下的受控子进程构建，不把后台草稿或媒体传进公开 GitHub 工作流。首次 ECS 部署仍需实测构建资源和更新时间；本机验收不能代替该测量。
- 首发内容取决于审核：每端 1–2 个完整重点业务。其余细分业务仅本机结构预览，不自动发布。
- 前端首页以[前端优化计划](前端优化计划.md)及[动效设计规范](frontend-motion-design.md)为当前目标：Empact 蓝 #125284、米白中段、少量红与青绿，三屏粒子动效和原生滚动吸附，ChatCircle 保留导航直达入口。早期文字驱动方案已归档；本次仅确认计划，未实现新首页。内页、真实内容和发布审核边界保留。
- 静态服务、CMS 均监听回环地址，复用现有 Caddy HTTPS 网关，不占用或重置 ChatCircle 的监听端口、数据和域名。
- 咨询由同域服务端收件，经 SMTP 成功交付后才显示成功；无有效收件配置时明确不可用。

## 执行顺序

1. 建立仓库基线、分支与数据契约。
2. 并行实现前台模板、CMS 与发布流程；补齐公开服务、咨询与部署脚本。
3. 类型检查、内容/链接/SEO 检查、鉴权/发布/回退/咨询集成测试和浏览器桌面移动端检查。
4. 核对依赖与生产构建，形成发布阻塞清单、运营说明和恢复操作。
5. 限定范围提交、推送并创建 ready PR；无生产凭据时不宣称公网已部署。

## 放行规则

技术检查不能替代素材授权、主体/备案和实际接收人确认。缺少生产输入时生产构建必须失败；本机预览使用显式 preview 模式并 noindex。不得填入虚构客户、统计、新闻或活动排期。

## 外部待办

公司审核者、咨询接收人、实际服务器规格/权限、DNS/证书/备案及公开内容与原图，需要公司提供。详见交付时的 readiness.md；不重复尝试无法获得的凭据。
